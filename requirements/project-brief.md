# Basket Ledger：从家庭小票看清花了什么钱，也看清买了什么

## 推荐

**可以做，而且这个版本比公开抓商超促销更强。** 推荐将 Basket Ledger 定义为家庭的**购买与食物支出账本**：每次购物后拍一张小票，AI 只负责提取和建议分类，用户确认后入账；家庭随时查看“今年在牛奶、零食、外卖食材、蔬果等类别分别花了多少”。

它保留了“买得是否划算”的后续空间，却不依赖未经许可的持续抓取、再发布和价格数据运营。第一版不称某个价格为“原价”或“虚假促销”，而是透明展示本家庭的最低 / 中位 / 最近购买价、样本数与日期。

你提出的“自动评估饮食健康”应改名为 **购买结构提示**：例如“本月已确认的购买金额中，蔬果占多少、含糖饮料/零食占多少、未能分类的项目有多少”。它不能诊断、评价某个人是否健康、给疾病/减重建议，也不能只根据一张小票得出家庭饮食结论。

## 先回答：原方案可以吗？

| 维度 | 结论 |
| --- | --- |
| 用户价值 | **有。** 家庭的真实、长期支出可见性是明确而具体的日常问题；同时 grocery competition 仍是 NZ 的公共议题，ComCom 2026 年报告称 major supermarkets 保有 80% 以上全国零售市场份额，价格在上升。[ComCom 2026 report](https://www.comcom.govt.nz/news-and-media/news-and-events/2026/comcom-releases-state-of-grocery-competition-report/) |
| “抓取”数据 | **不能直接假设可以。** 至少 Foodstuffs 线上购物条款只授予个人使用、可撤销的访问权，并禁止复制、重新发布、展示、传输或分发其线上服务内容，除非获明确许可。[Foodstuffs online terms, effective 15 June 2026](https://www.paknsave.co.nz/shop/terms-and-conditions) |
| “促销前原价”说法 | **高风险。** ComCom 要求价格及比较/markdown 声明清晰、准确、无歧义；“usual price”不能只是为了比较而编造。[ComCom pricing guidance](https://www.comcom.govt.nz/consumers/dealing-with-typical-situations/buying-goods-and-services/pricing/) |
| 竞争 | **直接赛道已有成熟产品。** Grocer 已提供 Kiwi grocery price comparison、跨店选择和 3 年以上的价格历史（视数据而定）。[Grocer](https://grocer.nz/), [Grocer Pro](https://grocer.nz/pro) |
| AI 读取小票 | **可行，但不能盲信。** 小票 OCR/LLM 只能输出候选商店、日期、项目、数量、价格与分类；用户确认后才入账。 |
| 饮食健康 | **可做成非医疗提示，不能做自动健康评估。** 小票没有完整营养成分；Health Star Rating 只适用于相似的包装食品，且是自愿标示，不能跨不同食品类别比较。[MPI: Health Star Ratings](https://www.mpi.govt.nz/food-business/labelling-composition-food-drinks/health-star-ratings-food-labelling/how-health-star-ratings-work) |
| 作品集可行性 | **很可行。** 做 receipt-first、可解释的家庭支出与购买结构工具，而不是一个可能被数据源封锁的比价 clone。 |

**结论：** 没有零售商书面许可、正式 API 或明确许可的数据集时，不要上线抓取器，更不要把其数据做成公开搜索与价格比较库。若日后拿到许可，可把官方 feed 接入为独立来源，并显示 `source / store / checked at / promotion terms`。

## 候选人匹配

你的 React、TypeScript、Node、MySQL、性能、稳定性、E2E 和运营平台背景，适合把这个做成一个可靠的“数据可信度产品”：

- 手机端拍照/录入小票，桌面端审阅家庭购物篮和价格趋势；
- OCR 是可选加速器，**人工确认是完整 fallback**；
- SKU/条码、包装规格、促销类型、置信度和来源可追溯，展示你做复杂状态和数据质量的能力；
- 权限、删除、图片私有存储、错误重试与可解释的统计规则，比单纯页面爬虫更符合生产工程。

工作假设：目标为 Auckland 前端 / Node 全栈岗位；每周 10–15 小时；先和 5–8 个家庭测试。假设不是已有事实。

## NZ 问题与证据

- ComCom 2026 年第三份年度报告覆盖 2025 财年，指出两大零售集团仍占全国市场 80% 以上、零售价格上升。[报告发布说明](https://www.comcom.govt.nz/news-and-media/news-and-events/2026/comcom-releases-state-of-grocery-competition-report/)
- 受规管的线下零售商自 2024-08-31、符合条件的线上零售商自 2025-08-31 起须显示 unit price；这使产品可帮助用户比较规格不同的包装，而非仅看红色“特价”标签。[ComCom unit-pricing information](https://www.comcom.govt.nz/regulated-industries/grocery/information-for-retailers-unit-pricing/)
- NZ 的 Nutrition Information Panel 可帮助比较能量、饱和脂肪、糖、钠等；但它在包装上，不会完整出现在一般小票上。[MPI: food labels](https://www.mpi.govt.nz/food-safety-home/how-read-food-labels)
- 这证明价格透明度与购买信息有公共价值，**不**证明家庭愿意上传小票或更换现有比价 App；这项行为必须验证。

## 产品概念

**一句话：** Basket Ledger 把家庭真实小票变成可确认、可搜索的购买账本，让一家人看清一年在什么商品和品类上花了多少钱，并得到谨慎的购买结构提示。

目标用户是会在 Woolworths、PAK'nSAVE、New World、Costco 或本地店之间切换的 2–5 人家庭。差异化是**个人可审计的历史**：每个结论都回到该家庭自己的收据、日期、包装与数量；没有数据就诚实显示“样本不足”。

### App + 网站分工

| 表面 | 自然任务 |
| --- | --- |
| 手机 PWA | 结账后拍摄小票；确认 AI 提取的商品、价格、数量和分类；一键标记“这是家庭共用/个人购买”。 |
| 网站 | 搜索商品、看本月/年度分类支出、合并重复品名、看购买结构、建立常买购物篮、导出/删除资料。 |
| 后端 | household、收据、行项目、AI extraction、用户确认、商品别名、支出分类、聚合统计、审计事件；数据只对本家庭可见。 |

## MVP

### 用户故事

1. 家庭成员能拍摄一张小票，并看到 AI 提取的商店、日期、总价和逐行项目；提取失败时能完整地手动输入。
2. 家庭成员能在提交前确认或修改项目名、数量、实付价及类别；未确认项目不进入统计。
3. 家庭成员能在网页看本月、今年、按商品和按类别的支出，并可筛选成员、门店和日期。
4. 家庭成员能把“同一商品的不同小票写法”合并为一个自定义商品，并查看最近价、最低价、中位价、样本数和最后购买日期。
5. 家庭成员能选择启用“购买结构提示”：查看已确认项目中各类的金额/次数与未分类比例；不显示个人健康分数。household owner 能邀请成员、删除收据原图和导出 CSV。

### 非目标

- 不抓取、镜像、复制或重新发布任何零售商网站、App、目录、图片、促销文案或价格资料。
- 不公开排名“哪家超市最便宜”、不提供“原价造假”判断、不对零售商合规作结论。
- 不做自动跨店 SKU 匹配、全 NZ 商品库、支付、购物下单、广告或返佣。
- 不依赖 OCR 正确率：识别失败时必须可以逐行手动录入；不把未确认结果用于统计。
- 不对任何个人、儿童或家庭作健康诊断、风险判断、治疗/饮食处方或减重建议；不收集病史、过敏、孕期、药物或身体指标。
- 不从小票臆测完整营养成分。没有用户确认的包装营养资料或 Health Star Rating 时，不对单品贴“健康/不健康”标签。

### 核心实体与规则

`Household`、`Member`、`Receipt`、`ReceiptImage`、`ReceiptLine`、`ExtractionCandidate`、`Confirmation`、`CanonicalProduct`、`ProductAlias`、`SpendCategory`、`PackSize`、`UnitPrice`、`PriceObservation`、`Basket`、`BasketItem`、`Insight`、`AuditEvent`。

规则：AI 输出仅为 `ExtractionCandidate`；用户确认后才生成 `ReceiptLine`、类别和 `PriceObservation`。unit price = 实付价格 ÷ 可解析的重量/体积/件数；不同规格默认不合并；结论显示样本数和时间窗；退货、multi-buy、优惠券和会员专享价先标为“可能不可比”。购买结构只报告已确认项目的金额/次数与覆盖率，不能称为健康评估。

### 4–6 周顺序

1. **第 0 周：** 访谈 5 个家庭，Figma 测试“录一张小票 → 改正 AI → 看年度类别花费 → 理解覆盖率”。
2. **第 1 周：** Next.js/TypeScript、登录/household、手动输入、私有 demo 数据与最小数据库。
3. **第 2 周：** 收据图片上传、AI/OCR 候选解析、人工确认界面、商品别名/类别、支出统计。
4. **第 3 周：** 移动 PWA、家庭共享、月/年图表、购买结构提示、单位价格与可解释 Insight、删除/导出与空/错态。
5. **第 4 周：** 单元、集成、E2E、CI、隐私说明、部署；试点使用合成/自愿小票。
6. **第 5–6 周（验证通过后）：** 评估/改进 OCR、离线草稿、包装条码手动扫描；不接入零售商抓取。营养面板扫描只作为探索，不做健康评分。

## 技术证明

- **栈：** Next.js、React、TypeScript、Node Route Handlers、PostgreSQL + Drizzle/Prisma、私有对象存储、PWA；OCR 仅作为 V2 可选服务。
- **AI 与测试：** 先用合成 NZ 风格小票建立真值集，测字段级 precision/recall、金额总和校验、低置信度阈值和“必须确认”流程；Vitest 测分类、单位价格、统计窗口与不可比标记；Playwright 覆盖“上传 → 改正 → 年度统计 → 删除”。AI 不可用时，手动路径仍可完成全部功能。
- **隐私：** 小票可能含门店、交易时间、会员号末尾和家庭消费习惯。图片私有默认；上传后提示用户涂抹/裁切会员识别号；不采集支付卡资料；可删除原图但保留用户选择的匿名价格行，或一并删除；analytics 不记录商品文本。健康相关资料即使不把产品变成 health service，也应按敏感资料最小化，绝不拿去训练或广告定向。
- **可访问性：** 手动输入是 OCR 的等价路径；键盘表格、错误摘要、图片替代文本、移动触控尺寸、明确的“未确认/不可比”状态。

## 验证实验与风险

| 项目 | 设计 |
| --- | --- |
| 假设 | 家庭愿意每周花 1–2 分钟确认一张小票，换取“今年钱花在哪、哪些商品变贵、购买结构有多完整”的清晰答案。 |
| 招募 | Auckland 朋友、邻居、华人社区中 5 个至少两人共同买菜的家庭；不以“帮他们省钱”承诺招募。 |
| 测量 | 用原型完成上传/确认三行、查看今年按类别花费、解释“未确认项目不计入统计”；随后一周收集自愿、已遮蔽的收据。 |
| 成功阈值 | 5 家中至少 4 家独立完成 3 行确认；至少 3 家一周后再记录一张；至少 3 人能正确解释图表的覆盖率与非医疗边界。 |
| Pivot / stop | 若用户只愿看图表而不愿确认小票，先缩为单人手动消费分类；若他们只想看全市场实时促销，则只做有书面许可的 retailer-feed discovery，不以抓取补足数据。 |

## 作品集证明与 V2

**案例标题：** “Turning messy grocery receipts into a privacy-first household spending ledger.”

Demo：手机上传小票 → AI 提取但要求确认 → 网站显示“今年按类别花费”与数据覆盖率 → 查看牛奶的家庭价格历史 → 显示购买结构提示的边界 → 删除原图。强调数据溯源、低置信度处理、隐私、可访问性和 E2E，而不是宣称 AI 能判断健康。

V2 的唯一跨店公开数据路径是：取得零售商/API/目录发行方**书面许可**，针对来源条款实现 feed adapter、保留来源与更新时间、严格按许可展示，并让零售商可纠错/下架。没有这些前提，不做公开促销库。
