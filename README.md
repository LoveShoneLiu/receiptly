# receiptly

一个以家庭为单位的私有购物小票账本。用户上传小票或手动录入，AI/OCR 只提供可编辑的候选内容；只有用户明确确认后，数据才会进入家庭账本、支出分析和历史价格视图。

## 产品要解决的问题

receiptly 帮助一个家庭回答：

- 在任意日期范围内，家庭实际花了多少钱？
- 钱主要花在哪些商品、品类和门店？
- 同一家庭商品过去在实际去过的门店分别花了多少钱？
- 有哪些可解释、非医疗性质的消费结构或节约提示？

它不是公开比价工具。所有价格结论只基于本家庭已确认的小票数据。

## MVP 流程

1. 用户登录、创建或加入一个家庭。
2. 通过相机、相册、文件上传，或完整手动录入创建小票草稿。
3. AI/OCR 异步提取候选；失败、低置信度或离线时，手动录入仍可完成整个流程。
4. 用户逐行确认或修改门店、日期、商品、数量、规格、金额、分类与促销可比性。
5. 仅在头部、有效行和总额都明确确认后，小票进入 `confirmed` 状态。
6. 已确认数据可用于按日期、商品、类别、门店和成员的分析，以及家庭商品的历史购买价格。

## 核心页面

- 登录与家庭：创建/加入家庭、成员和邀请管理。
- 首页：本月总额、待确认收据、快捷上传入口。
- 新建收据：拍照、选择图片/文件、上传进度与手动录入。
- 确认收据：逐行编辑、批量分类、总额校验、重复提示。
- 支出分析：日期和多维筛选、排名、图表、表格与行项目下钻。
- 商品详情：家庭自定义商品、别名、跨店历史价格、单位价与可比性说明。
- 洞察：预算、确定性节约提示和中性购买结构提示。
- 设置与隐私：家庭、分类、导出、删除和数据边界。

## 不可突破的边界

- AI 提取永远只是候选；草稿、未确认、冲突和已删除数据绝不能进入统计、价格或洞察。
- 不抓取、镜像、复制或公开展示零售商网站、商品或促销数据。
- 仅称为“本家庭历史购买价”；不得宣称市场最低价、原价、实时价格或全网比价。
- 不做健康、疾病、营养、减重、儿童、孕期、过敏或药物建议。购买记录不等于实际食用，也不能代表个人健康。
- 小票原图和家庭数据必须私有；服务端必须验证用户、家庭成员关系和角色。
- 完整手动录入是 OCR 的等价路径，OCR 或网络故障不得阻断入账。

## 计划中的技术方向

需求文档建议采用 Next.js、React、TypeScript、Node Route Handlers、PostgreSQL、私有对象存储与 PWA。具体依赖、架构和部署方案尚未固定；实现前请先确认并记录技术决策。

## 当前应用

`apps/mobile` 是 iOS 优先的 Expo / React Native 应用。它当前包含 receiptly 首页骨架、iOS 相机/相册权限文案，以及“添加小票”入口；小票上传、手动录入、登录和 API 尚待后续切片实现。

启动方式：

```bash
cd apps/mobile
npm run ios
```

首次运行需要本机已安装 Xcode Simulator；也可执行 `npm start` 后用 Expo Go 打开开发服务器。
